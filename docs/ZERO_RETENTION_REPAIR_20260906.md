## 覆盖全部计数的充分条件

若高价分支所有路线的旧司机留存率都**恰好为零**，高价继续等待的乘客收益
不依赖早期司机计数。给定一名标记旧司机，增加任意路线、任意数量的其他旧司机：

1. 不改变高价继续等待的收益；
2. 只能弱增加立即成交的收益；
3. 只能弱增加低价继续等待的收益。

因此，只需证明“仅该标记司机”时，高价等待收益被立即接受和低价等待收益的
最大值严格压住。代码在所有分段线性折点及两个竞争收益的交点验证该不等式，
正收益顶点保持原有 1e-10 安全边距。该证明覆盖全部 Poisson 计数，未丢弃尾部。
任意小但正的留存概率（测试包括 1e-250）均使此新增充分条件失效。

旧算法使用“该司机必定留存”的高价尾部上界，即使真实高价留存全零也可能过松。
新增充分条件补足这个遗漏；不改动支付、随机 OD、乘客择优规则或既有离轨信念。
仍是带边距的浮点验证，不是精确算术证书。

## 独立版本及复现

新增 `zero_retention_envelope.py` 和 `zero_retention_checkpoint_solver.py`。
后者复制既有检查点求解流程，仅替换评估器；冷启动同伦规则、阈值和模型均未改变。
`run_zero_retention_repairs.py` 对三项已完成失败菜单，以原成本/路线支撑、训练种子、
alpha 分配和相同冷启动同伦重新求解。没有从失败 profile 温启动，也没有覆盖原结果。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -u run_zero_retention_repairs.py --output runs/zero_retention_repairs_20260906
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -u audit_zero_retention_repairs.py --root runs/zero_retention_repairs_20260906
```

第一条完成后再执行第二条。第一条保留旧审计种子便于诊断比较；第二条在全部
新 profile 冻结后，以从未用于原审计和训练的新种子对每个菜单进行两组百万样本审计，
使用原每菜单 alpha 的一半。验收不依赖重复使用原失败审计数据。
每组完整结果、原失败结果和 profile、源与输入指纹均保存；两条命令均有独占锁。

发布归档位于 `results/zero_retention_repairs_20260906/`：含原失败结果及策略、
新策略及最终检查点、逐阶段日志、支撑和输入请求、新旧完整审计及六路运行快照。
在全新 checkout 中复现时，先将 `inputs/m1`、`inputs/m3` 的 request/support
分别复制到 `runs/m1_outer_search_20260906`、`runs/m3_outer_search_20260906`，
再把每项 `original_result.json`、`original_profile.npz` 还原为对应
`m*/menu_00***/result.json`、`profile.npz`。仅在不存在旧输出的工作区做此还原；
不得覆盖正在运行的工作区。随后执行上述两个命令，以当前来源重新冷启动并审计。
